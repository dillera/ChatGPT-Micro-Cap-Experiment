```python
def check_and_enforce_stops(
    client: TastytradeClient,
    snapshot: AccountSnapshot,
    dry_run: bool = True,
) -> list[dict]:
```

Implementation:
1. Read the `positions` table from SQLite to get stored `stop_loss` values.
2. For each position in `snapshot.positions` that has a matching `stop_loss` in the DB:
   a. Call `client.get_quote(symbol)` to get live `(bid, ask, spread_pct)`.
   b. Compute `mid = (bid + ask) / 2`.
   c. If `mid <= stop_loss`, the stop is triggered.
3. For triggered stops:
   a. Log with `logger.warning("Stop-loss triggered for {symbol}: price ${mid:.2f} <= stop ${stop_loss:.2f}")`.
   b. If `dry_run=False`: place a sell order using the broker client's existing order mechanism. Use a limit sell at the bid price (conservative). Record the trade in SQLite `trades` table with `source='stop_loss'`.
   c. If `dry_run=True`: log the would-be sell but do not submit.
4. Return a list of dicts, one per triggered stop: `{"symbol": str, "trigger_price": float, "stop_loss": float, "status": "sold"|"dry_run"|"skipped"}`.

For the sell order, create a simple limit sell (NOT an OTOCO -- we are closing, not opening). Add a helper method or use a direct broker call. Since TastytradeClient only has `place_otoco_order`, add a `place_sell_order` method to the return dict with a TODO comment noting that a simple sell method should be added to broker.py. For now, log the sell action and record it to DB but call `client.place_otoco_order` is inappropriate for sells. Instead:
- For dry_run=True: just log and return status "dry_run"
- For dry_run=False: log a WARNING that a simple sell method is needed and return status "needs_sell_method" (Phase 4 will add this). Record to trades table regardless for audit trail.

IMPORTANT: The GTC stop orders from Phase 2 OTOCO provide between-cycle safety. This module handles the ADDITIONAL check at cycle start for positions where the native GTC stop may not have fired yet (e.g., gap scenarios, or positions from before OTOCO was implemented).

**Stage 0: Lockfile** -- Acquire exclusive lock on `data/cycle.lock` using `fcntl.flock(LOCK_EX | LOCK_NB)`. If cannot acquire, log and exit with `{"status": "skipped", "reason": "another cycle running"}`. Use a context manager pattern:

```python
LOCK_PATH = Path(get_settings().db_path).parent / "cycle.lock"

def _acquire_lock():
    """Acquire exclusive lockfile. Returns file handle or None."""
    LOCK_PATH.parent.mkdir(parents=True, exist_ok=True)
    fh = open(LOCK_PATH, "w")
    try:
        fcntl.flock(fh, fcntl.LOCK_EX | fcntl.LOCK_NB)
        return fh
    except OSError:
        fh.close()
        return None
```

**Stage 1: Initialize** -- Call `init_db()`, create `TastytradeClient`, call `client.authenticate()`.

**Stage 2: Market status check** -- Check if today is a trading day. Use `datetime.now()` weekday check (0-4 = Mon-Fri). For v1, skip weekend days with `{"status": "skipped", "reason": "market closed (weekend)"}`. A proper market calendar can be added in Phase 5. Log: `logger.info("Market status: open" or "closed")`.

**Stage 3: Account sync** -- `snapshot = client.get_account_snapshot()`, `client.sync_positions_to_db(snapshot)`. Log account summary.

**Stage 4: Circuit breaker check** -- Read circuit_breaker table from SQLite. If `status != 'ACTIVE'`, check for env var `OVERRIDE_CIRCUIT_BREAKER=1`. If override present and status is HALTED_DAILY or HALTED_DRAWDOWN, reset to ACTIVE (log the reset). If no override, return `{"status": "halted", "reason": cb_status}`. This is a READ-ONLY check here -- the actual trip logic lives in Plan 02's circuit_breaker module. For now, just read the status:

```python
conn = get_db()
row = conn.execute("SELECT status, reason FROM circuit_breaker WHERE id=1").fetchone()
cb_status = row["status"] if row else "ACTIVE"
```

If status is not ACTIVE and no override:
```python
if cb_status != "ACTIVE":
    override = os.environ.get("OVERRIDE_CIRCUIT_BREAKER") == "1"
    if override:
        conn.execute("UPDATE circuit_breaker SET status='ACTIVE', reset_at=? WHERE id=1", (datetime.now().isoformat(),))
        conn.commit()
        logger.warning("Circuit breaker manually overridden from {}", cb_status)
    else:
        logger.warning("Circuit breaker is {}: {}", cb_status, row["reason"])
        return {"status": "halted", "reason": f"circuit_breaker: {cb_status}"}
```

**Stage 5: Stop-loss enforcement** -- Call `check_and_enforce_stops(client, snapshot, dry_run)`. Log results.

**Stage 6: Consensus** -- Call `run_consensus_cycle(snapshot.positions, snapshot.buying_power, candidates)`. For `candidates`, use the symbols from current positions (for SELL/HOLD analysis). In v1, the candidate list is the existing positions -- new BUY candidates require a screening module (Phase 5). If no approved trades, log and continue to snapshot stage.

**Stage 7: Order execution** -- For each `approved_trade` in consensus result, call `execute_trade(client, trade, Decimal(str(snapshot.buying_power)), dry_run)`. Collect results.

**Stage 8: Post-trade snapshot** -- Re-fetch account state: `post_snapshot = client.get_account_snapshot()`. (This snapshot will be used by the circuit breaker in Plan 02 and the logger in Plan 03.)

**Return value:** A dict with all cycle data:
```python
{

}
```

**Top-level exception handling:** Wrap the entire function body in try/except. On ANY unhandled exception, log with `logger.exception("Cycle failed: {}", e)` and return `{"status": "error", "reason": str(e)}`. Always release lockfile in finally block.

**Exit codes are NOT managed here** -- the CLI layer (Plan 03) translates status to exit codes.
