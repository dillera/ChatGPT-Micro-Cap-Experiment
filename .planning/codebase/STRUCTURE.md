## Directory Purposes

**Root Directory:**
- Purpose: Main project files and entry points
- Key files: `trading_script.py` (main engine), `simple_automation.py` (LLM automation), configuration/docs

**Scripts and CSV Files/:**
- Purpose: Production portfolio state for the experiment (daily updates)
- Contains: Active portfolio CSV, trade log CSV, local copies of graph/processor scripts
- Key files: `chatgpt_portfolio_update.csv` (current holdings), `chatgpt_trade_log.csv` (all trades executed)

**Start Your Own/:**
- Purpose: Template repository for users starting their own experiment
- Contains: Empty CSV templates, README with setup instructions, local copies of utility scripts
- Key files: `README.md` (user quick-start), template CSVs

**Experiment Details/:**
- Purpose: Documentation, methodology, prompts, and research metadata
- Contains: Disclaimers, FAQs, LLM prompt templates, links to historical ChatGPT conversations
- Key files: `Deep Research Index.md` (navigation), `Prompts.md` (exact LLM instructions)

**Weekly Deep Research (MD)/ and (PDF)/:**
- Purpose: Weekly performance summaries and detailed research reports
- Contains: One markdown/PDF per week (Week 1 Summary.md, Week 2 Report.pdf, etc.)
- Key files: Latest week's analysis (updated every Friday/Monday)

**Other/:**
- Purpose: Legal, community, and miscellaneous project files
- Contains: Code of conduct, license, legacy ignore patterns, reference images
- Key files: `LICENSE.txt`, `CODE_OF_CONDUCT.md`

**.planning/codebase/:**
- Purpose: Analysis documents for GSD planning and execution tools
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md (future), TESTING.md (future), CONCERNS.md (future)
- Key files: This directory generated by GSD map-codebase command

## Key File Locations

**Entry Points:**
- `trading_script.py`: Main trading engine; call `python trading_script.py` or import functions
- `simple_automation.py`: LLM automation; call `python simple_automation.py --api-key=...`
- `Scripts and CSV Files/Generate_Graph.py`: Chart generator; call `python Generate_Graph.py`

**Configuration:**
- `requirements.txt`: Python package dependencies
- `tickers.json` (optional, not in repo): Benchmark ticker configuration; if present, overrides DEFAULT_BENCHMARKS
- Environment variables: `ASOF_DATE=YYYY-MM-DD` (backtesting override), `OPENAI_API_KEY` (LLM automation)

**Core Logic:**
- `trading_script.py` lines 323–368: `download_price_data()` (multi-stage fallback for market data)
- `trading_script.py` lines 395–619: `process_portfolio()` (daily trading loop, stop-loss checks, PnL calculation)
- `simple_automation.py` lines 32–81: `generate_trading_prompt()` (LLM prompt construction)
- `simple_automation.py` lines 105–119: `parse_llm_response()` (JSON extraction from LLM response)

**Testing:**
- No formal test suite present; manual testing via dry-run modes and CSV inspection

**Data Files:**
- `Scripts and CSV Files/chatgpt_portfolio_update.csv`: Portfolio state (one row per holding + daily TOTAL rows)
- `Scripts and CSV Files/chatgpt_trade_log.csv`: Trade execution audit trail
- `Scripts and CSV Files/llm_responses.jsonl`: LLM interaction log (created by simple_automation.py)

## Naming Conventions

**Files:**
- Snake_case with underscores: `trading_script.py`, `simple_automation.py`, `Generate_Graph.py`
- CSV files: `chatgpt_portfolio_update.csv`, `chatgpt_trade_log.csv`, `llm_responses.jsonl`
- Documentation: Title Case + .md or .pdf: `README.md`, `AUTOMATION_README.md`, `Week 1 Summary.md`

**Functions:**
- Snake_case: `download_price_data()`, `process_portfolio()`, `log_manual_buy()`, `generate_trading_prompt()`
- Private (internal) functions start with underscore: `_yahoo_download()`, `_stooq_download()`, `_normalize_ohlcv()`
- Public API: no underscore prefix

**Variables:**
- Snake_case: `portfolio_df`, `total_equity`, `buy_price`, `stop_loss`
- Constants: UPPER_CASE: `DEFAULT_BENCHMARKS`, `DATA_DIR`, `PORTFOLIO_CSV`, `STOOQ_BLOCKLIST`
- Global mutable state: `ASOF_DATE` (marked in code), accessed via `set_asof()` setter

**Types:**
- Use PascalCase for custom types: `FetchResult` (dataclass, line 192–195 in trading_script.py)
- Use lowercase for built-in types: `pd.DataFrame`, `dict`, `list`, `float`

**Directories:**
- Title Case with spaces: `Scripts and CSV Files/`, `Start Your Own/`, `Experiment Details/`, `Weekly Deep Research (MD)/`
- Underscore for programmatic paths: `.planning/codebase/`

## Where to Add New Code

**New Feature:**
- Core trading logic: Add functions to `trading_script.py` in appropriate layer (data access, portfolio operations, utilities)
- LLM automation enhancements: Modify `simple_automation.py` (prompt generation, trade execution, response parsing)
- Primary code: `trading_script.py` or `simple_automation.py` (root directory)
- Tests: N/A (no test directory; use manual testing with dry-run modes)
- Example: New buy order type → add function `log_manual_buy_oco()` in `trading_script.py` around line 652

**New Component/Module:**
- If standalone utility: Create new `.py` file in root directory (e.g., `risk_calculator.py`)
- If visualization: Add to `Scripts and CSV Files/` (e.g., `Generate_Performance_Heatmap.py`)
- If documentation: Add to `Experiment Details/` for methodology or `Weekly Deep Research (MD)/` for research
- Import pattern: Other modules import via `from trading_script import process_portfolio, download_price_data` (see simple_automation.py line 20–23)

**Utilities:**
- Shared helpers: Add to `trading_script.py` if widely used by portfolio ops; mark with leading underscore if internal-only
- Data processing helpers: Add to `Scripts and CSV Files/ProcessPortfolio.py` (light-duty utility module)
- Math/stats helpers: Consider new module `analytics.py` if complex; otherwise add to existing files

**User-Facing Templates:**
- Copy new scripts to `Start Your Own/` after adding to root/Scripts directories
- Update `Start Your Own/README.md` with setup instructions for new features
- Maintain template CSV headers in `Start Your Own/*.csv` files
